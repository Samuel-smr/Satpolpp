PENJELASAN SEQUENCE DIAGRAM SIPRAJA
Pembaruan: 21 September 2026

ALUR 1 — PELAPOR BERTANYA KEPADA ASISTEN AI
1. Pelapor membuka halaman Lapor.
2. Browser mengirim message dan maksimal delapan riwayat pesan ke POST /lapor/asisten-ai.
3. AskAiAssistantRequest memvalidasi panjang, role riwayat, dan bentuk payload.
4. Rate limiter membatasi sepuluh permintaan per menit.
5. AiAssistantController memanggil GeminiAssistant.
6. GeminiAssistant membaca key/model dari config, memanggil Google Gemini dengan timeout dan retry terbatas.
7. Jawaban Bahasa Indonesia dikembalikan ke browser.
8. Jika provider gagal, controller mengembalikan 503 dengan pesan aman; secret dan detail provider tidak ditampilkan.

ALUR 2 — WARGA MENGIRIM LAPORAN
1. Pelapor mengisi satu form Lapor tanpa pilihan jenis dan tanpa NIK.
2. StoreGuestReportRequest memvalidasi telepon, nama opsional, deskripsi, lokasi, koordinat, dan foto.
3. PelaporController memperoleh/membuat GuestAccess.
4. Sistem membuat Report bertipe lapor dengan status submitted.
5. Sistem membuat ReportStatusHistory awal dan menyimpan lampiran.
6. Admin aktif menerima notifikasi.
7. Pelapor memperoleh kode laporan; token tamu tetap di browser.

ALUR 3 — ADMIN MENANGANI LAPORAN
1. Admin membuka daftar dan detail Report.
2. Admin memajukan status satu tahap melalui ReportStatusController.
3. Sistem memeriksa status awal, menyimpan status baru, riwayat, dan audit.
4. Saat in_progress, Admin membuka form penyelesaian.
5. CompleteReportController memvalidasi petugas aktif, hasil, lokasi, dan bukti.
6. Dalam transaksi, sistem membuat Activity eksternal, menghubungkan Officer dan Attachment, lalu menandai Report completed.
7. Pelapor dapat melihat hasil dan mengirim feedback satu kali.

ALUR 4 — SUPER ADMIN MEMANTAU PERSEBARAN
1. Super Admin membuka dashboard.
2. SuperAdminController mengambil statistik serta titik Report/Activity berkoordinat.
3. Dashboard merender kartu, grafik, dan peta pada halaman yang sama.
4. Super Admin dapat membuka detail yang diizinkan dari konteks dashboard.
5. Tidak ada navigasi atau endpoint halaman Peta terpisah.

ALUR 5 — PENGELOLAAN KEGIATAN INTERNAL
1. Admin/Super Admin membuka form kegiatan.
2. StoreInternalActivityRequest memvalidasi data, koordinat, petugas, temuan, dan dokumentasi.
3. ActivityController menyimpan Activity internal beserta relasi dalam transaksi.
4. Perubahan dan penghapusan mengikuti validasi, otorisasi, soft delete, serta audit.

CATATAN
- OperationalZone dan OrganizationalUnit tidak terlibat dalam alur mana pun.
- Laporan tidak bercabang menjadi Darurat atau Informasi & Pengaduan.
- API key Gemini hanya digunakan oleh backend.
