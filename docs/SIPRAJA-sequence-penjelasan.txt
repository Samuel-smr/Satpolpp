SEQUENCE DIAGRAM SIPRAJA — PELAPOR, ADMIN, DAN SUPER ADMIN
Dibuat berdasarkan implementasi lokal yang diperiksa pada 14 September 2026.

MEMBUKA DI DRAW.IO
1. Buka draw.io / diagrams.net.
2. Pilih File > Open From > Device, lalu SIPRAJA-sequence.drawio.
3. Pilih tab halaman proses yang diperlukan. Gunakan zoom untuk membaca detail.
4. Objek peserta, garis lifeline, pesan dan frame dapat diedit.
5. Untuk presentasi, ekspor halaman terpilih ke PDF, SVG atau PNG dari draw.io.
6. Alternatif: salin satu blok @startuml ... @enduml pada SIPRAJA-sequence.puml
   ke editor PlantUML. Berkas TXT ini adalah penjelasan, bukan kode diagram.

CARA MEMBACA
- Urutan waktu dari atas ke bawah. Angka pada pesan memudahkan pencocokan dengan uraian.
- A = pengguna; B = halaman/browser; C = aplikasi Laravel/controller;
  D = database melalui Eloquent. Peserta tambahan hanya muncul jika diperlukan.
- Aktor 'Admin / Super Admin' berarti salah satu peran melakukan proses yang sama,
  bukan kedua pengguna harus mengirim permintaan bersama.
- Kotak peserta dan garis vertikal putus-putus adalah lifeline.
- Panah penuh menunjukkan permintaan/pemanggilan; putus-putus menunjukkan respons.
- Panah kembali ke lifeline sendiri menunjukkan pengolahan lokal.
- Frame alt berisi alternatif yang saling eksklusif; pilih cabang sesuai kondisi.
- Frame opt dijalankan hanya jika kondisi terpenuhi; loop mengulang pesan di dalamnya.
- Tidak semua query atau respons framework digambar satu per satu. Pesan agregat
  seperti 'UPDATE ... dan audit' menyatakan rangkaian tindakan, bukan satu query SQL.
- Database adalah abstraksi Eloquent/DB, bukan controller kedua.
- C menggabungkan pipeline HTTP: middleware, route binding, Form Request, controller.
  Form Request berjalan sebelum metode controller; digabung agar diagram terbaca.
- Request privat membutuhkan sesi sah dan role sesuai routes/web.php.
  Pemeriksaan auth tidak diulang di setiap gambar. Kegagalan umum dapat menghasilkan
  redirect login, 403, 404 atau kesalahan validasi sesuai tahap kegagalan.
- Form biasa umumnya kembali dengan error validasi; permintaan JSON dapat menerima 422.
- Pengiriman form dengan CSRF tidak sah ditolak oleh framework; bukan jalur sukses.
- Perintah simpan memicu proses server; batal/silang tidak menyimpan data.
- BEGIN/COMMIT/ROLLBACK ditampilkan sebagai konsep transaksi Laravel.
  File fisik tidak ikut rollback database: controller melakukan pembersihan terpisah.
- Beberapa controller CRUD sederhana tidak membungkus write dan audit dalam transaksi;
  diagram tidak menambahkan transaksi yang tidak ada.
- Tidak ada sesi login untuk pelapor. Akses laporan sendiri memakai cookie guest.
- Sequence diagram menjelaskan urutan komunikasi. Dokumen use case sebelumnya
  menjelaskan tujuan pengguna; kode referensinya dipertahankan di sini.

BATAS IMPLEMENTASI YANG PENTING
1. Admin dan super admin adalah role terpisah; bukan pewarisan semua izin.
2. Tahap laporan: Submitted → Received → Verifying → InProgress → Completed.
   Tidak ada tahap ditolak. Completed menggunakan form penyelesaian.
3. Penyelesaian membuat satu kegiatan eksternal; category NULL; koordinat disalin
   ke laporan. Alamat laporan asli tidak diganti oleh proses ini; kegiatan menyimpan
   alamat penanganannya sendiri.
4. Kegiatan internal dapat ditambah/edit/hapus oleh admin dan super admin.
   Kegiatan eksternal dilihat melalui laporan terkait; super admin baca saja.
5. Feedback hanya untuk pemilik akses tamu, setelah selesai, dan satu kali.
6. Peta form melakukan pencarian/geolokasi di browser. Koordinat masuk database
   ketika form laporan/kegiatan disimpan, bukan saat marker digeser.
7. Notifikasi laporan baru menggunakan kanal database Laravel secara langsung;
   tidak diasumsikan antrean worker, push realtime, email atau WhatsApp.
8. Ekspor PDF/Excel kegiatan berjalan di browser memakai data dari server.
9. Arsip maksimal 20 MB menurut validasi aplikasi; konfigurasi PHP/web server
   juga harus mendukung ukuran request. Diagram tidak mengubah konfigurasi itu.
10. Monitoring hanya menunjukkan audit yang benar-benar dicatat kode.
11. Alur kegagalan penting digambar; ini bukan enumerasi semua kegagalan OS/jaringan.
    Bila database gagal di dalam transaksi, perubahan rollback dan controller
    membersihkan file baru sesuai implementasinya.
12. Notifikasi dibuat setelah transaksi laporan selesai. Kegagalan notifikasi
    tidak otomatis membatalkan laporan yang sudah di-commit.

SQ01 — Login dan logout
Aktor: Admin / Super Admin
Penangan: AuthController
Referensi use case: C01, C05
Penjelasan dan aturan:
Login memeriksa akun aktif. Logout membatalkan sesi. RateLimiter ditampilkan sebagai komponen logis aplikasi, bukan diasumsikan tabel tertentu.
Urutan pesan dan kondisi:
1. Admin / Super Admin --> Halaman / Browser: Isi username/email dan kata sandi
2. Halaman / Browser --> AuthController: POST /login
3. AuthController --> AuthController: Validasi input; periksa pembatas percobaan
ALT [batas percobaan terlampaui]
  4. AuthController --respons--> Halaman / Browser: Pesan tunggu; login ditolak
ELSE [boleh mencoba]
  5. AuthController --> Database / Eloquent: Cari akun aktif; autentikasi kredensial
  6. Database / Eloquent --respons--> AuthController: Hasil autentikasi
  ALT [kredensial tidak cocok]
    7. AuthController --> AuthController: Tambah hit percobaan gagal
    8. AuthController --respons--> Halaman / Browser: Kembali ke login dengan pesan kesalahan
  ELSE [kredensial cocok]
    9. AuthController --> AuthController: Bersihkan hit; regenerasi sesi
    10. AuthController --respons--> Halaman / Browser: Redirect dashboard sesuai role
    11. Halaman / Browser --respons--> Admin / Super Admin: Tampilkan dashboard
    OPT [pengguna memilih keluar]
      12. Admin / Super Admin --> Halaman / Browser: Klik Logout
      13. Halaman / Browser --> AuthController: POST /logout
      14. AuthController --> AuthController: Logout; invalidate sesi; regenerasi token
      15. AuthController --respons--> Halaman / Browser: Redirect beranda publik
    END
  END
END

SQ02 — Pelapor mengirim laporan
Aktor: Pelapor
Penangan: PelaporController
Referensi use case: P01
Penjelasan dan aturan:
Tanpa login; NIK wajib untuk darurat; foto opsional maksimal 3 × 5 MB. Token mentah disimpan dalam cookie, hash di database. Notifikasi memakai kanal database, bukan email/WhatsApp.
Urutan pesan dan kondisi:
1. Pelapor --> Halaman / Browser: Isi jenis, telepon, NIK sesuai kondisi, deskripsi dan alamat
2. Pelapor --> Halaman / Browser: Opsional pilih foto; setujui pernyataan; Kirim
3. Halaman / Browser --> PelaporController: POST /lapor (multipart + cookie tamu)
4. PelaporController --> PelaporController: StoreGuestReportRequest: validasi
ALT [input tidak valid]
  5. PelaporController --respons--> Halaman / Browser: Kembali ke form dengan kesalahan
ELSE [valid]
  OPT [foto dilampirkan]
    6. PelaporController --> Storage lokal: Simpan foto ke reports/evidence
    7. Storage lokal --respons--> PelaporController: Path dan metadata foto
  END
  8. PelaporController --> Database / Eloquent: Temukan akses tamu valid atau buat token hash baru
  9. Database / Eloquent --respons--> PelaporController: GuestAccess
  10. PelaporController --> Database / Eloquent: BEGIN; buat kode unik dan laporan Submitted
  11. PelaporController --> Database / Eloquent: Simpan riwayat dan metadata lampiran
  ALT [transaksi berhasil]
    12. PelaporController --> Database / Eloquent: COMMIT
    13. PelaporController --> Database / Eloquent: Ambil pengguna Admin aktif
    14. Database / Eloquent --respons--> PelaporController: Daftar penerima
    15. PelaporController --> Notifikasi Laravel: Kirim NewReportNotification
    16. Notifikasi Laravel --> Database / Eloquent: Simpan notifikasi database
    17. PelaporController --respons--> Halaman / Browser: Redirect /lapor + kode + cookie akses tamu
    18. Halaman / Browser --respons--> Pelapor: Tampilkan kode laporan
  ELSE [penyimpanan/transaksi gagal]
    19. PelaporController --> Database / Eloquent: ROLLBACK bila transaksi dimulai
    20. PelaporController --> Storage lokal: Bersihkan foto yang sempat tersimpan
    21. PelaporController --respons--> Halaman / Browser: Permintaan gagal; laporan belum berhasil dibuat
  END
END

SQ03 — Pelapor memantau status
Aktor: Pelapor
Penangan: PelaporController
Referensi use case: P02
Penjelasan dan aturan:
Daftar berasal dari cookie akses tamu valid pada browser tersebut. Kode laporan bukan pengganti cookie untuk mengambil laporan milik sendiri.
Urutan pesan dan kondisi:
1. Pelapor --> Halaman / Browser: Buka menu Status

4. Database / Eloquent --respons--> PelaporController: Akses tamu atau tidak ditemukan

  5. PelaporController --respons--> Halaman / Browser: Halaman status dengan daftar kosong
ELSE [akses valid]
  6. PelaporController --> Database / Eloquent: Perbarui last_used_at; ambil laporan dan riwayat milik akses
  7. Database / Eloquent --respons--> PelaporController: Laporan terurut terbaru
  8. PelaporController --> PelaporController: Susun data status dan informasi feedback
  9. PelaporController --respons--> Halaman / Browser: Render halaman Status
  10. Halaman / Browser --respons--> Pelapor: Tampilkan daftar dan tahap laporan
END

SQ04 — Pelapor memberi feedback
Aktor: Pelapor
Penangan: PelaporController
Referensi use case: P03
Penjelasan dan aturan:
Rating 1–5, komentar opsional. Kepemilikan dan status selesai diperiksa server. Feedback kedua ditolak dengan 409.
Urutan pesan dan kondisi:
1. Pelapor --> Halaman / Browser: Pilih laporan selesai; isi rating dan komentar
2. Halaman / Browser --> PelaporController: POST /status/{code}/feedback
3. PelaporController --> PelaporController: Validasi rating/komentar
ALT [input salah]
  4. PelaporController --respons--> Halaman / Browser: Kesalahan validasi
ELSE [input valid]
  5. PelaporController --> Database / Eloquent: Periksa akses tamu dan kepemilikan laporan
  6. Database / Eloquent --respons--> PelaporController: Hasil pemeriksaan
  ALT [bukan pemilik / akses tidak valid]
    7. PelaporController --respons--> Halaman / Browser: 404
  ELSE [pemilik sah]
    8. PelaporController --> Database / Eloquent: BEGIN; lockForUpdate laporan
    9. Database / Eloquent --respons--> PelaporController: Status dan feedback terbaru
    ALT [belum selesai]
      10. PelaporController --> Database / Eloquent: ROLLBACK
      11. PelaporController --respons--> Halaman / Browser: 404
    ELSE [feedback sudah dikirim]
      12. PelaporController --> Database / Eloquent: ROLLBACK
      13. PelaporController --respons--> Halaman / Browser: 409: feedback sudah pernah dikirim
    ELSE [selesai dan belum feedback]
      14. PelaporController --> Database / Eloquent: UPDATE rating, komentar, waktu; COMMIT
      15. PelaporController --respons--> Halaman / Browser: JSON feedback berhasil disimpan
      16. Halaman / Browser --respons--> Pelapor: Tampilkan keberhasilan
    END
  END
END

Aktor: Admin
Penangan: AdminReportController
Referensi use case: A02

Online wajib platform; offline wajib NIK 16 digit. Koordinat wajib, kategori tidak diminta. Foto opsional maksimal 3 × 5 MB.

1. Admin --> Halaman / Browser: Buka Tambah Laporan
2. Halaman / Browser --> AdminReportController: GET /admin/pengaduan/create
3. AdminReportController --respons--> Halaman / Browser: Form sumber, identitas, lokasi dan bukti
4. Admin --> Halaman / Browser: Pilih sumber; isi identitas dan deskripsi
ALT [online]
  5. Halaman / Browser --> Halaman / Browser: Tampilkan pilihan platform; NIK tidak wajib
ELSE [offline]
  6. Halaman / Browser --> Halaman / Browser: Wajibkan NIK; sembunyikan platform
END
7. Admin --> Halaman / Browser: Pilih titik lokasi dan foto opsional; Simpan
8. Halaman / Browser --> AdminReportController: POST /admin/pengaduan
9. AdminReportController --> AdminReportController: Validasi melalui StoreAdminReportRequest
ALT [tidak valid]
  10. AdminReportController --respons--> Halaman / Browser: Kembali ke form dengan kesalahan
ELSE [valid]
  OPT [ada foto]
    11. AdminReportController --> Storage lokal: Simpan bukti
    12. Storage lokal --respons--> AdminReportController: Path foto
  END
  13. AdminReportController --> Database / Eloquent: Transaksi: buat laporan Submitted, riwayat dan lampiran
  ALT [berhasil]
    14. Database / Eloquent --respons--> AdminReportController: Data tersimpan
    15. AdminReportController --> Database / Eloquent: Ambil Admin aktif; simpan NewReportNotification via kanal database
    16. AdminReportController --respons--> Halaman / Browser: Redirect detail laporan
  ELSE [gagal]
    17. AdminReportController --> Storage lokal: Bersihkan bukti yang sempat disimpan
    18. AdminReportController --respons--> Halaman / Browser: Permintaan gagal
  END

SQ06 — Admin memajukan status
Aktor: Admin
Penangan: ReportStatusController
Referensi use case: A03
Penjelasan dan aturan:
Tidak ada alur status ditolak atau kembali ke tahap sebelumnya. Ditindaklanjuti hanya dapat diselesaikan melalui form penyelesaian.
Urutan pesan dan kondisi:
1. Admin --> Halaman / Browser: Buka detail; klik tahap berikutnya dan isi catatan opsional
2. Halaman / Browser --> ReportStatusController: PATCH /admin/pengaduan/{code}/status
3. ReportStatusController --> ReportStatusController: Validasi current_status dan catatan
4. ReportStatusController --> Database / Eloquent: BEGIN; lockForUpdate laporan
5. Database / Eloquent --respons--> ReportStatusController: Status terbaru
ALT [status awal sudah berubah]
  6. ReportStatusController --> Database / Eloquent: ROLLBACK
  7. ReportStatusController --respons--> Halaman / Browser: Minta muat ulang halaman
ELSE [status cocok]
  8. ReportStatusController --> ReportStatusController: Hitung nextProcessingStatus
  ALT [tidak ada tahap berikutnya]
    9. ReportStatusController --> Database / Eloquent: ROLLBACK
    10. ReportStatusController --respons--> Halaman / Browser: Gunakan penyelesaian / laporan sudah selesai
  ELSE [tahap berikutnya tersedia]
    11. ReportStatusController --> Database / Eloquent: UPDATE status; INSERT riwayat dan audit; COMMIT
    12. ReportStatusController --respons--> Halaman / Browser: Redirect detail dengan status baru
    13. Halaman / Browser --respons--> Admin: Dibuat → Diterima → Diverifikasi → Ditindaklanjuti
  END

SQ07 — Admin menyelesaikan laporan
Aktor: Admin
Penangan: CompleteReportController
Referensi use case: A04, A05
Penjelasan dan aturan:
Bukti 1–3 foto, minimal satu petugas aktif, tanggal tidak melewati hari ini. Semua perubahan DB berada dalam satu transaksi. Penyimpanan file mendahului transaksi dan dibersihkan bila gagal.
Urutan pesan dan kondisi:
1. Admin --> Halaman / Browser: Isi nama, tanggal, hasil, lokasi/koordinat dan petugas
2. Admin --> Halaman / Browser: Unggah bukti; Simpan dan Buat Kegiatan Eksternal
3. Halaman / Browser --> CompleteReportController: POST /admin/pengaduan/{code}/complete
4. CompleteReportController --> CompleteReportController: Validasi form penyelesaian
ALT [input tidak valid]
  5. CompleteReportController --respons--> Halaman / Browser: Kembali dengan kesalahan
ELSE [input valid]
  6. CompleteReportController --> Storage lokal: Simpan foto penanganan
  7. Storage lokal --respons--> CompleteReportController: Path dan metadata
  8. CompleteReportController --> Database / Eloquent: BEGIN; kunci laporan; cek kegiatan termasuk terhapus
  9. CompleteReportController --> Database / Eloquent: Kunci dan periksa petugas aktif
  10. Database / Eloquent --respons--> CompleteReportController: Status, kegiatan dan petugas terbaru
  ALT [status berubah / bukan InProgress / kegiatan sudah ada / petugas tidak aktif]
    11. CompleteReportController --> Database / Eloquent: ROLLBACK
    12. CompleteReportController --> Storage lokal: Hapus foto baru
    13. CompleteReportController --respons--> Halaman / Browser: Tolak; muat ulang/perbaiki form
  ELSE [pemeriksaan lolos]
    14. CompleteReportController --> Database / Eloquent: INSERT kegiatan External, report_id, category NULL
    15. CompleteReportController --> Database / Eloquent: INSERT temuan, relasi petugas dan lampiran public
    16. CompleteReportController --> Database / Eloquent: UPDATE laporan Completed, waktu, latitude dan longitude
    17. CompleteReportController --> Database / Eloquent: INSERT riwayat dan audit; COMMIT
    18. CompleteReportController --respons--> Halaman / Browser: Redirect detail laporan selesai
    19. Halaman / Browser --respons--> Admin: Tampilkan hasil, peta dan preview penanganan
  END
END

SQ08 — Daftar detail dan hapus laporan
Aktor: Admin / Super Admin
Penangan: AdminController + AdminReportController
Referensi use case: A01, A06, A07, K07
Penjelasan dan aturan:
Daftar pengaduan, feedback dan penghapusan hanya admin. Super admin membuka detail terkait kegiatan dengan mode baca saja. Lampiran diambil melalui endpoint terotorisasi.
Urutan pesan dan kondisi:
1. Admin / Super Admin --> Halaman / Browser: Pilih daftar/detail laporan yang diizinkan
2. Halaman / Browser --> AdminController + AdminReportController: GET halaman sesuai role
3. AdminController + AdminReportController --> Database / Eloquent: Ambil laporan, relasi, riwayat dan data detail
4. Database / Eloquent --respons--> AdminController + AdminReportController: Data laporan
5. AdminController + AdminReportController --respons--> Halaman / Browser: Render detail; super admin baca saja
OPT [browser memuat bukti]
  6. Halaman / Browser --> AdminController + AdminReportController: GET endpoint lampiran yang sesuai
  7. AdminController + AdminReportController --> AdminController + AdminReportController: Periksa relasi, audience dan jenis file
  8. AdminController + AdminReportController --> Storage lokal: Periksa keberadaan; baca file
  9. Storage lokal --respons--> AdminController + AdminReportController: Isi gambar
  10. AdminController + AdminReportController --respons--> Halaman / Browser: Stream gambar dengan header aman
END
OPT [Admin memilih hapus dan konfirmasi]
  11. Halaman / Browser --> AdminController + AdminReportController: DELETE /admin/pengaduan/{code}
  12. AdminController + AdminReportController --> Database / Eloquent: Soft delete laporan dan simpan audit
  13. AdminController + AdminReportController --respons--> Halaman / Browser: Kembali ke daftar aktif
END
OPT [Admin membuka Feedback]
  14. Halaman / Browser --> AdminController + AdminReportController: GET /admin/feedback
  15. AdminController + AdminReportController --> Database / Eloquent: Ambil feedback laporan
  16. Database / Eloquent --respons--> AdminController + AdminReportController: Rating dan komentar
  17. AdminController + AdminReportController --respons--> Halaman / Browser: Render halaman feedback
END

SQ10 — Edit dan hapus kegiatan internal
Aktor: Admin / Super Admin
Penangan: ActivityController
Referensi use case: K03, K04, K05
Penjelasan dan aturan:
Tidak berlaku untuk kegiatan eksternal. Edit memeriksa current_updated_at dan total dokumentasi lama + baru maksimal 3. Penghapusan dokumentasi memakai controller lampiran. Saat transaksi penghapusan lampiran gagal, file karantina dipindahkan kembali ke path asal.
Urutan pesan dan kondisi:
1. Admin / Super Admin --> Halaman / Browser: Buka kegiatan internal dan pilih aksi
ALT [Edit]
  2. Halaman / Browser --> ActivityController: GET kegiatan/{id}/edit
  3. ActivityController --> Database / Eloquent: Ambil kegiatan dan pilihan form
  4. Database / Eloquent --respons--> ActivityController: Data tersimpan
  5. ActivityController --respons--> Halaman / Browser: Form terisi + current_updated_at
  6. Admin / Super Admin --> Halaman / Browser: Ubah data dan simpan
  7. Halaman / Browser --> ActivityController: PUT kegiatan/{id} + temuan + dokumentasi baru
  8. ActivityController --> ActivityController: Validasi; pastikan Internal
  OPT [foto baru]
    9. ActivityController --> Storage lokal: Simpan foto baru
  END
  10. ActivityController --> Database / Eloquent: BEGIN; kunci kegiatan; periksa versi, total maksimal 3 file, referensi
  ALT [konflik / referensi tidak valid / foto berlebih]
    11. ActivityController --> Database / Eloquent: ROLLBACK
    12. ActivityController --> Storage lokal: Bersihkan foto baru
    13. ActivityController --respons--> Halaman / Browser: Muat ulang atau perbaiki
  ELSE [valid]
    14. ActivityController --> Database / Eloquent: UPDATE kegiatan; sync petugas dan temuan; tambah lampiran dan audit; COMMIT
    15. ActivityController --respons--> Halaman / Browser: Redirect detail yang diperbarui
  END
ELSE [Hapus kegiatan; konfirmasi]
  16. Halaman / Browser --> ActivityController: DELETE kegiatan/{id}
  17. ActivityController --> Database / Eloquent: Kunci dan pastikan Internal; soft delete; audit
  18. ActivityController --respons--> Halaman / Browser: Redirect daftar kegiatan
ELSE [Hapus dokumentasi; konfirmasi]
  19. Halaman / Browser --> ActivityController: DELETE endpoint lampiran internal
