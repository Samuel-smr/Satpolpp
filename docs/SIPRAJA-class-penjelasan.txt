CAKUPAN DAN DASAR
Diagram class domain/persistensi, berisi 15 model App\\Models, 1 tabel asosiasi,
1 model notifikasi Laravel, dan 16 enum. Controller, request, Blade, seeder,
factory serta tabel teknis cache/jobs/sessions/password_reset_tokens tidak
dimasukkan sebagai class domain. Perilaku controller telah dirinci pada
dokumen sequence yang dibuat sebelumnya.
Skema diturunkan dari migration termasuk perubahan terakhir, bukan dari
pembacaan data pribadi atau pembuktian semua migration sudah diterapkan di DB aktif.

NOTASI
- Bagian atas: stereotype, nama class dan tabel.
- Bagian tengah: atribut logis beserta tipe data/cast.
- Bagian bawah: metode model yang benar-benar dideklarasikan.
- + = public; # = protected. Atribut tidak diberi visibility palsu karena
  atribut Eloquent diakses dinamis, bukan properti private yang dideklarasikan.
- ? = nullable menurut skema, bukan otomatis boleh kosong pada form.
- PK = primary key; FK = foreign key; unique = batas keunikan DB.
- 1 = tepat satu; 0..1 = opsional maksimal satu; 0..* = nol sampai banyak.
  Angka di dekat class menunjukkan jumlah objek class itu per objek lawannya.
- Relasi tanpa panah = asosiasi; bukan urutan proses dan bukan kepemilikan komposisi.
- Garis putus-putus bermakna menurut label: polimorfik atau FK skema saja.
- XOR Attachment: satu lampiran milik tepat satu Report ATAU satu Activity.
  Tidak berarti lampiran tanpa pemilik atau milik keduanya sekaligus.
- Angka relasi mengikuti kemungkinan skema, termasuk keadaan belum ada data.
  Aplikasi dapat menambahkan syarat lebih ketat, misalnya kegiatan baru
  wajib minimal satu petugas aktif.
- SoftDeletes = delete logis menggunakan deleted_at.
- Date/Time/DateTime dan decimal adalah tipe konseptual untuk dokumentasi.
  Eloquent mengembalikan decimal:7 sebagai string; start_time di SQL adalah
  TIME dan dicast datetime:H:i. Atribut timestamps() dapat bernilai NULL.
- Tidak semua tipe hasil relasi mengindikasikan objek langsung: HasMany,
  BelongsTo, HasOne, MorphTo dan BelongsToMany adalah objek relasi Eloquent.
- casts() adalah metode protected konfigurasi tipe, bukan fitur pengguna.
- Metode bawaan save(), delete(), query(), create(), dll diwarisi framework;
  tidak disalin berulang pada setiap class.
- DatabaseNotification menampilkan tipe hasil logis method; signature vendor
  tidak selalu mendeklarasikan return type secara eksplisit.

PEWARISAN DAN TRAIT
- User extends Illuminate\\Foundation\\Auth\\User (Authenticatable),
  yang pada akhirnya extends Eloquent Model.
- Empat belas model lokal selain User extends Eloquent Model.
- DatabaseNotification adalah class vendor yang extends Model.
- Seluruh model lokal memakai HasFactory.
- User memakai Notifiable; relasi notifications()/unreadNotifications()
  tersedia melalui trait, bukan metode lokal yang dibuat di User.php.
- Model dengan SoftDeletes: Report, Activity, Officer, OrganizationalUnit,
  OperationalZone, Archive, Asset.
- ReportStatusHistory dan AuditLog menggunakan UPDATED_AT = null.
- ActivityOfficer hanya nama dokumentasi untuk tabel activity_officer;
  tidak ada file App\\Models\\ActivityOfficer.php.
- Pewarisan framework juga disertakan pada versi PlantUML; halaman draw.io
  menekankan domain dan asosiasi agar tidak penuh garis ke satu superclass.

PEMETAAN TIGA AKTOR
Pelapor:
  Diwakili akses tamu GuestAccess dan atribut identitas pada Report.
  Tidak ada class login Pelapor atau subclass User untuk pelapor.
Admin dan Super Admin:

  Bukan hubungan pewarisan Admin → SuperAdmin. Hak akses diatur Gate.

TEMUAN STRUKTUR TERKINI
1. Report.feedback_rating, feedback_comment, feedback_submitted_at adalah
   feedback; tidak ada model/tabel Feedback terpisah.
2. Activity.evaluation_notes, evaluation_obstacles, evaluated_at dan
   evaluated_by_user_id adalah evaluasi; tidak ada model Evaluation terpisah.
3. Activity.category sudah menggantikan operational_category dan berupa
   nama template/string nullable. activity_template_id adalah FK sebenarnya.
   Nama kategori bukan FK ke name dan template.name tidak unique pada skema.
4. ActivityTemplate.operational_category masih menggunakan OperationalCategory.
   Archive.operational_category sekarang berupa string nama template kegiatan aktif.
5. Report.category masih ada dan dicast ReportCategory; form create baru
   tidak mengisinya. Kolom tidak dihilangkan dari diagram hanya karena form
   tidak menampilkannya.
6. Officer.employee_number = NIP; position = jabatan; work_unit_name = nama
   satuan kerja; unit_name = unit kerja. Ketiganya string pilihan, bukan model baru.
7. Officer.user_id, organizational_unit_id, operational_zone_id dan status
   masih ada. Form saat ini tidak otomatis memetakan nama satuan/unit ke FK.
8. Officer rank/email/phone/address/joined_at telah dihapus oleh migration
   2026_09_14_035025; tidak dicantumkan sebagai atribut terkini.
9. Officer.user_id adalah FK unique tetapi tidak ada metode user() di model.
   Diagram menandai relasi ini 'FK saja', tidak mengarang metode baru.
10. OrganizationalUnit.leader_officer_id dan Officer.organizational_unit_id
    adalah dua hubungan berbeda: pimpinan dan keanggotaan.
11. Report–Activity: 0..1 pada kedua ujung. report_id Activity nullable dan unique.
    Internal tidak punya report; eksternal hasil penyelesaian terkait satu report.
12. Relasi Activity–Officer adalah many-to-many melalui pivot unik per pasangan.
13. Attachment menggunakan morphMap report/activity dari AppServiceProvider.
    Kolom attachable_id tidak memiliki FK SQL lintas tabel; konsistensi pemilik
    ditegakkan aplikasi. Multiplicity menggambarkan hubungan model yang sah.
14. AuditLog.subject_type/subject_id adalah metadata; tidak ada subject() MorphTo.
    Tidak digambar FK/polimorfisme ORM yang sebenarnya tidak dideklarasikan.
15. Archive bertindak sebagai folder metadata dan mempunyai 1–3 ArchiveFile.
    Bukti laporan/dokumentasi kegiatan tetap memakai Attachment.
16. Activity mempunyai nol atau banyak ActivityFinding. Setiap temuan menyimpan
    jenis (orang/barang), jumlah, dan satuan (buah/batang/botol/orang).
17. User memiliki notifikasi DatabaseNotification melalui Notifiable.
    Multiplicity pada halaman menunjukkan penggunaan User di SIPRAJA;
    struktur notifiable Laravel secara umum dapat menunjuk tipe model lain.
18. Soft delete tidak menjalankan aksi FK hard delete. nullable/nullOnDelete
    dapat membuat hubungan pembuat/pelaku opsional, sedangkan restrictOnDelete
    membatasi penghapusan fisik; detail berada di migration.

CATATAN PEMAKAIAN
Diagram adalah representasi implementasi, bukan usulan refactor. Nama class
memakai nama PHP agar dapat dicocokkan dengan kode. Nama layar Indonesia dijelaskan
pada dokumen pendamping use case/sequence. Satu class yang muncul pada beberapa
halaman adalah class yang sama, bukan class duplikat dalam aplikasi.
